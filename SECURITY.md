# Security

Report vulnerabilities privately through GitHub's "Report a vulnerability"
(Security tab of OpenThinkAi/pm) rather than a public issue.

## Supply chain

### cargo-deny

`deny.toml` checks advisories, licenses (permissive, MIT OR Apache-2.0
compatible only), bans (duplicate crate versions warn) and sources
(crates.io only). Run it before a release or a dependency bump:

```sh
cargo install --locked cargo-deny
cargo deny check
```

It is deliberately not a stamp `required_check`: it fetches the RustSec
advisory database, so it needs network and its result changes with no
change to the tree.

### Advisory triage (2026-09-30)

- **RUSTSEC-2020-0041 (sized-chunks, unsound)**: does not apply. It is
  patched in `sized-chunks >= 0.6.3`; the locked version is 0.6.5.
- **RUSTSEC-2026-0248 / 0251 / 0247 (im, sized-chunks, bitmaps,
  unmaintained)**: upstream archived them in May 2026. They arrive only as
  `loro 1.16.2 -> loro-internal -> im 15.1.0`, and 1.16.2 is the latest loro,
  so there is no upgrade path (a loro major bump would also risk the
  snapshot/update wire format and is not taken casually). Ignored in
  `deny.toml` with a reason; unmaintained, not a known vulnerability. All
  three are MPL-2.0 (file-level copyleft, used unmodified), allowed by a
  per-crate license exception. Revisit when loro drops `im`.
- **RUSTSEC-2023-0089 (atomic-polyfill, unmaintained)**: via `loro-internal ->
  postcard 1.1.3 (latest) -> heapless 0.7`. Only compiled for targets without
  native atomic compare-and-swap (e.g. thumbv6m); no pm target is one, so it
  is in `Cargo.lock` but never built. Ignored with a reason so lockfile
  scanners such as `cargo audit` stay quiet too.
- `smallstr` (RUSTSEC-2026-0215) comes from `yrs`, a dev-dependency used by
  tests only; `deny.toml` sets `exclude-dev = true`.

### Container image

`crates/pm-hub/Dockerfile` pins both base images by digest on Debian 13
(trixie). Bump deliberately with
`docker buildx imagetools inspect debian:trixie-slim` (and the `rust` tag),
then rebuild.

### Vendored view bundles

`crates/pm/views/vendor/*.js` are generated by
`crates/pm/views-vendor/build.ts`, which also writes `vendor.sha256`.
`cargo test` (`views::tests::vendored_bundles_match_manifest`) hashes the
committed bundles against it offline, so a hand-edited bundle fails. At
runtime the unpacked view cache is re-verified against the embedded views
before each reuse and re-unpacked if anything differs.

The cache fingerprint (the cache directory's name, and the re-verification
above) is SHA-256 over every file's length-prefixed path and bytes (AGT-1465;
it was FNV-1a).

### Terminal output

Ticket text, comments, hold reasons and hub error bodies arrive from other
actors through `pm sync`. Every human-readable (non-`--json`) output strips
terminal controls — C0/C1 (ESC/CSI/OSC introducers, CR, DEL), bidi
overrides and isolates, line/paragraph separators — via `crates/pm/src/text.rs`
(newlines and tabs kept only in multi-line sinks: descriptions, comments).
`--json` output is exactly what is stored.

### ui-leaf runtime

pm hands the ui-leaf runtime its API token. `ui_leaf.path` is used as given;
a `ui-leaf` found on `PATH` is launched only when it is the npm-installed
`@openthink/ui-leaf` package (see `docs/app-api.md`). This is provenance, not
a content hash.

### View CSP

The `pm app` view page keeps `'wasm-unsafe-eval'` (for loro's wasm) and
`'unsafe-inline'` in `script-src`. The latter stays because ui-leaf serves
views as a single page with inline scripts and supports no nonce or hash;
see `docs/app-api.md`.
